The decisions behind the system

Follow the implementation, tests, and evidence.

01 / Applied AI

Separate format validity from factual correctness.

Parse structured answers, constrain cited physical pages, and demonstrate that a schema-valid answer can still be wrong.

The fixture checks an interface; it is not a new semantic-accuracy benchmark.

Implementation · Tests · Evidence

02 / Data science

Diagnose retrieval before blaming the reader.

Evaluate page retrieval separately from supplied-evidence reading and end-to-end answer quality.

The small, repeatedly used development panel limits generalization claims.

Implementation · Tests · Evidence

03 / ML engineering

Make interrupted work recoverable.

Use durable reader checkpoints and artifact identities so completed questions need not be repeated after a failure.

The public code illustrates recovery contracts; private GPU state is not distributed.

Implementation · Tests · Evidence

04 / Data science

Preserve negative and incomplete results.

Keep official, development, structural-coverage, and factual-correctness claims separate in a machine-checkable closeout.

Aggregate consistency does not independently authenticate private receipts.

Implementation · Tests · Evidence

05 / Data science

Test the failure boundary, not only the happy path.

Execute visible authored challenges against the shipped engine; separate retrieval or decision coverage from successful outcomes and retain every failure.

These synthetic diagnostics do not estimate neural-model quality or production accuracy.

Implementation · Tests · Evidence

06 / ML engineering

Make an exported answer independently replayable.

Rerun retrieval and validate separate human edits, source passages and receipts against the actual browser implementation.

Replay verifies computation, not semantic correctness or authorship.

What the public evidence establishes.

The public checks execute authored response fixtures through the actual parsing and citation validators, and recompute aggregate closeout consistency. The optional browser checks exercise lexical retrieval on synthetic documents. These are different from model-backed question answering.

Full-test documents, generated answers, exact routing rules, private checkpoints, model caches, and operational cloud locations remain excluded. The two unresolved historical answers remain unresolved.

Headline signals are recorded project measurements, not results newly obtained by this review. Links point to the current default branch; the local receipt binds the exact reviewed file bytes with SHA-256. A checksum establishes consistency, not independent authentication of historical results.
